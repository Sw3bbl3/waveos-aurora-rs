WaveUI

State in, interface out.

An app has four parts: its state, the messages that change it, update and view. If you know SwiftUI or Elm, you already know the shape.

use waveui::prelude::*;

struct Counter { count: i64 }

#[derive(Clone)]
enum Msg { Add, Reset }

impl App for Counter {
    type Message = Msg;
    fn title(&self) -> String { "Counter".into() }

    fn update(&mut self, msg: Msg, _cx: &mut Context<Msg>) {
        match msg {
            Msg::Add => self.count += 1,
            Msg::Reset => self.count = 0,
        }
    }

    fn view(&self, _env: &Env) -> View<'_, Msg> { /* as above */ }
}

corekit::entry!(main);
fn main(_: corekit::Args) -> i32 {
    waveui::run(Counter { count: 0 })
}

Controls, cards and sheets: radius::CONTROL, CARD, SHEET.

Context: talking to the system

update receives a Context: send messages and timers (send, after), open apps and files, use the clipboard, post notifications, close the window, and move focus or scroll. For background work, return an interval from poll_interval and do it in poll.

Sheets, alerts and menus

Return a view from sheet to show a dialog; the window waits until it goes. Alert builds the standard question with default, cancel and destructive roles. Button::menu and context_menu add menus to anything.

Design guidelines

Calm, clear and quick.

How built-in apps look and behave, so yours feels at home next to them. WaveUI's standard views do most of this for you.

Clarity

Content comes first. Plenty of space, a clear type hierarchy and few colours, so the important things stand out.

Depth

Sidebars and toolbars are translucent, like living water over the desktop. Cards and sheets lift what they hold.

Deference

The interface supports the work. Prefer familiar controls, and keep chrome quiet.

Respect

Follow appearance, accent, text size, Reduce Motion and Reduce Transparency. Never lose anyone's work.

Layout

  • Navigation in a leading sidebar with SplitView; content on the trailing side.
  • Actions in a toolbar, the most frequent at the trailing end.
  • Space by the scale: 8 within a group, 16 between groups, 24 around a window's content.

Colour

  • Semantic colours only; they adapt to light and dark.
  • The accent marks selection, links and the one primary action.
  • Red is for destructive actions and errors. Never rely on colour alone.

Controls

  • One prominent button per view; bordered for the rest.
  • Toggles in settings; segmented pickers for two to five short choices.
  • A bar when you know how much is left, a spinner when you don't.

Motion

  • Under 250 ms, and only to show where something came from or went.
  • Nothing animates with Reduce Motion on; check env.reduce_motion.

Keyboard

  • Everything works without a pointer: Tab, Space, Return, Escape.
  • Support Ctrl+N, O, S, W, Z, C, V and F, and show shortcuts in menus.

Writing

  • Sentence case, short labels that say what happens.
  • Errors say what happened and what to do next, without blame or codes.
  • WaveOS ships in English and Canadian French. Translate yours too.

Studio and Terminal

From idea to installed app.

Create a project in Studio with New, or from Terminal. Studio's Design view writes WaveUI code for simple screens, and never overwrites your src/main.rs.

# a new WaveUI project
wavesdk new /Documents/Projects/MyApp dev.example.myapp "My App"

MyApp/
  manifest.toml        identity, version and SDK
  Cargo.toml           corekit and waveui from the SDK
  src/main.rs          your code
  src/generated_ui.rs  written from the layout
  layouts/main.ui      heading, label, button, toggle

Rust, Cargo and LLVM don't run inside WaveOS yet. Build on a host with cargo xtask build, then package the result. Build and Run in Studio say what's missing; they never pretend to succeed.

Ship

Package, test, install.

A .gina is an uncompressed ustar archive with manifest.toml at its root, at most 64 MiB and 1,024 entries. The validator checks paths, checksums, bounds, resources, x86-64, SDK 0.6 to 0.9 and ABI 1.

format = 1
id = "dev.example.myapp"
name = "My App"
developer = "Example Developer"
version = "1.0.0"
architecture = "x86_64"
sdk = "0.9"
abi = 1
entry = "bin/app"
icon = ""
resources = []
extensions = []

Package with cargo xtask package manifest.toml app.elf MyApp.gina, then open it in Files or run wavesdk install. Updates stage a new generation and switch only after it is written and synced; app data in /AppData survives.
